# Пачка

Мини-приложение для сбора кооп-пачки: участник заходит по ссылке-приглашению
и отвечает на опрос перед заходом в мир — когда сможет играть, какие
настройки мира хочет и какие моды предлагает поставить.

Одна страница, четыре блока: тепловая карта «когда сходится пачка», ввод
своей доступности по дням и часам, селектор душноты (модификаторы мира
Valheim) и лента предложений по модам.

## Стек

Статика на GitHub Pages + Supabase. Своего сервера нет.

- **Vite + TypeScript**, без UI-фреймворка
- **Supabase** — вход через Discord и хранилище с правами на уровне строк
- **GitHub Pages** — хостинг, деплой из Actions

Единственная рантайм-зависимость — `@supabase/supabase-js`, и та грузится
отдельным чанком, только если бэкенд настроен. Демо-сборка — 13 КБ gzip.

Подробности о том, почему выбрано именно это и как обходятся ограничения
статического хостинга: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Локальный запуск

```bash
npm install
npm run dev
```

Без переменных окружения страница поднимается в **демо-режиме**: ответы
девяти участников сгенерированы, свои сохраняются в `localStorage`, входа
нет. Этого достаточно, чтобы смотреть и править интерфейс.

## Боевой режим

### 1. Проект Supabase

Создать проект, затем в SQL Editor выполнить:

1. `supabase/schema.sql` — таблицы, функции и политики доступа;
2. `supabase/seed.sql` — завести пачку (там же подставляются игра, окно дат
   и обложка).

Запрос в конце `seed.sql` вернёт `invite_code` — это и есть GUID
приглашения.

### 2. Discord

1. [Discord Developer Portal](https://discord.com/developers/applications) →
   **New Application** → **OAuth2**.
2. В **Redirects** добавить callback проекта Supabase:
   `https://<project-ref>.supabase.co/auth/v1/callback`.
3. Скопировать **Client ID** и **Client Secret**.
4. В Supabase: **Authentication → Providers → Discord** — включить и
   вставить их. Секрет остаётся там и в репозиторий не попадает.
5. В **Authentication → URL Configuration → Redirect URLs** добавить адрес
   страницы: `https://<юзер>.github.io/<репо>/`.

### 3. GitHub Pages

**Settings → Pages → Source: GitHub Actions**, затем в
**Settings → Secrets and variables → Actions → Variables** задать:

| Переменная | Значение |
| --- | --- |
| `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `SUPABASE_ANON_KEY` | публичный anon-ключ проекта |
| `PACK_SLUG` | слаг пачки из `seed.sql`, например `valheim` |

Это именно **Variables**, а не Secrets: значения публичные и по смыслу
попадают в клиент. Доступ ограничивает не секретность ключа, а RLS-политики
в БД.

Пуш в `master` собирает и публикует страницу.

### 4. Ссылка для пачки

```
https://<юзер>.github.io/<репо>/#/join/<invite_code>
```

Её и кидают в Discord. Первый заход по ней после входа добавляет человека в
пачку; повторные — просто открывают опрос и обновляют имя с аватаром.

## Проверки

```bash
npm run build                 # типы + сборка
./supabase/test/run.sh        # политики доступа на локальном Postgres
```

`run.sh` поднимает схему на чистом Postgres с заглушками Supabase и
проверяет, что анонимный ключ видит только превью пачки по GUID, что без
приглашения в пачку не попасть, что участники видят ответы друг друга, но не
могут их подделать, и что значения модификаторов и часов ограничены. Оба
шага крутятся в CI (`.github/workflows/ci.yml`).

## Структура

```
src/
  data/valheim.ts      формулировки модификаторов и расчёт душноты
  data/pack.ts         конфиг пачки
  backend/             types · local (демо) · supabase (боевой)
  ui/                  панели страницы
  app.ts               состояние, агрегация карты, подсчёт голосов
  main.ts              вход и экраны авторизации
supabase/
  schema.sql           таблицы, RPC и RLS
  seed.sql             создание пачки
  test/                проверка политик доступа
```

## Настройка пачки

Игра, название, обложка и окно планирования лежат в строке таблицы `packs` —
меняются через `seed.sql` или прямо в консоли Supabase, без пересборки.
Тексты модификаторов мира взяты из русской локализации Valheim и менять их
не следует; единственный кастомный пункт — «Перемещение предметов после
первого путешествия», это договорённость пачки, а не настройка сервера.
